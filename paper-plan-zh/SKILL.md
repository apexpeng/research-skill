# Paper Plan 中文版: 从研究结论到论文大纲

基于 **$ARGUMENTS** 生成结构化中文论文大纲。

## 常量

- **TARGET_VENUE = `中文期刊/会议`** — 默认目标。支持的格式：中文期刊、EI会议、SCI期刊
- **MAX_PAGES** — 正文页数限制。从首页到结论结束（不含参考文献和附录）
- **OUTPUT_LANG = `zh-CN`** — 默认输出语言

## 输入

期望以下文件存在于项目目录：

1. **draft_zh.md** 或 **NARRATIVE_REPORT.md** — 含主张和证据的研究叙事
2. **claims_evidence_matrix.md** — 主张-证据矩阵
3. **实验结果** — JSON 文件在 `figures/`、日志、表格
4. **review_round_*.md** — 审查记录（如有）

如果不存在，询问用户用 3-5 句话描述论文贡献。

## 工作流程

### Step 1: 提取主张和证据

读取所有可用的叙事文档，提取：

1. **核心主张**（3-5 个主要贡献点）
2. **每条主张的证据**（哪个实验、哪个指标、哪个图表）
3. **已知弱点**（来自审查反馈）
4. **建议的表述方式**（来自审查结论）

构建**主张-证据矩阵**：

```markdown
| 主张 | 证据 | 状态 | 对应章节 |
|------|------|------|---------|
| [主张 1] | [实验A, 指标B] | 有支持 | §3.2 |
| [主张 2] | [实验C] | 部分支持 | §4.1 |
```

### Step 2: 确定论文类型和结构

根据 TARGET_VENUE 和论文内容分类选择结构。

**论文类型**：

**实证/诊断论文：**
```
1. 引言 (1.5 页)
2. 相关工作 (1 页)
3. 方法/实验Setup (1.5 页)
4. 实验结果 (3 页)
5. 讨论 (1 页)
6. 结论 (0.5 页)
```

**理论+实验论文：**
```
1. 引言 (1.5 页)
2. 相关工作 (1 页)
3. 预备知识与问题建模 (1.5 页)
4. 理论结果 (2 页)
5. 实验验证 (2 页)
6. 结论 (0.5 页)
```

**工程/系统论文：**
```
1. 引言 (1.5 页)
2. 相关工作与背景 (1 页)
3. 系统设计 (2 页)
4. 实现与实验 (2.5 页)
5. 讨论与局限性 (0.5 页)
6. 结论 (0.5 页)
```

### Step 3: 章节规划

每个 section 指定：

```markdown
### §0 摘要
- **一句话问题**：[解决了什么gap]
- **方法**：我们做了什么（一句话）
- **关键结果**：最有说服力的定量发现
- **意义**：为什么重要
- **预计长度**：200-300 字
- **自包含检查**：读者不理解正文能理解摘要吗？

### §1 引言
- **研究背景**：2-3句描述问题的背景和重要性
- **研究缺口**：现有方法的不足
- **关键问题**：本文回答的具体研究问题
- **主要贡献**：编号列表（2-4条），对应主张-证据矩阵
- **Hero Figure**：描述 Figure 1 应该展示什么
- **预计长度**：1-1.5 页
- **关键引用**：这里要引用的 3-5 篇论文

### §2 相关工作
- **研究主题分类**：2-4 个相关工作类别
- **现有方法分析**：每个类别的方法、优缺点
- **本文定位**：与现有工作的区别和创新点
- **最短长度**：0.8-1 页（至少 3 段有实质内容的综合分析）

### §3 方法/实验设计
- **符号定义**：关键符号及其含义
- **问题形式化**：形式化设定
- **方法描述**：算法、技术细节或实验设计
- **理论命题**：定理、命题（如适用）
- **预计长度**：1.5-2 页

### §4 实验结果
- **实验设置**：数据集、baseline、实现细节
- **主实验图表**：
  - Fig 1：[描述，类型：柱状/折线/表格，展示什么对比]
  - Fig 2：[描述]
  - 表 1：[展示什么，哪些方法/baseline 被比较]
- **数据来源**：[哪个 JSON 文件 / 实验结果]

### §5 讨论/局限性
- **结果分析**：主要发现的深入分析
- **与现有方法比较**：优势和改进空间
- **局限性诚实评估**：方法的适用范围和不足
- **预计长度**：0.5-1 页

### §6 结论
- **贡献总结**：重新表述（不是从引言复制粘贴）
- **未来工作**：1-2 个具体研究方向
- **预计长度**：0.3-0.5 页
```

### Step 4: Figure 规划

列出每个图表和表格：

```markdown
## Figure 规划

| ID | 类型 | 描述 | 数据来源 | 优先级 |
|----|------|------|---------|--------|
| Fig 1 | 架构图/流程图 | 系统概览 | 手动绘制 | 高 |
| Fig 2 | 折线图 | 性能对比曲线 | figures/exp_A.json | 高 |
| Fig 3 | 柱状图 | 消融实验结果 | figures/ablation.json | 中 |
| 表 1 | 比较表 | 主实验结果 vs baselines | figures/main_results.json | 高 |
```

**Figure 1 / Hero Figure 关键描述**：
- 展示什么核心对比或系统概览
- 视觉上应该突出什么信息
- 清晰的图注草案

### Step 5: 引用规划

每个 section 列出需要的引用：

```markdown
## 引用规划
- §1 引言：[paper1], [paper2]（问题动机）
- §2 相关：[paper3]-[paper8]（按类别分组）
- §3 方法：[paper9]（baseline），[paper10]（基于的技术）
- §4 实验：[paper11]等（对比方法）
```

**引用规则**：
1. **不要从记忆生成引用信息** — 总是通过搜索验证
2. 每个引用必须正确：作者、年份、期刊/会议
3. 有疑问的引用用 `[待验证]` 标记
4. 优先使用正式发表版本

### Step 6: 输出

将最终大纲保存到项目根目录的 `PAPER_PLAN.md`：

```markdown
# 论文计划

**标题**：[工作标题]
**目标期刊/会议**：[目标 venue]
**类型**：[实证/理论/系统]
**日期**：[今天]
**页数预算**：正文 [X] 页（首页到结论结束，不含参考文献和附录）
**章节数**：[N]

## 主张-证据矩阵
[from Step 1]

## 论文结构
[from Step 2-3，按章节]

## Figure 规划
[from Step 4，含详细 hero figure 描述]

## 引用规划
[from Step 5]

## 下一步
- [ ] /paper-figure 生成所有图表（数据驱动图表）
- [ ] /paper-write-zh 起草中文 LaTeX
- [ ] /paper-compile 编译 PDF
```

## 与 ARIS paper-plan 的区别

| 方面 | ARIS paper-plan | 本 skill |
|------|----------------|---------|
| 输出语言 | 英文 | **中文** |
| 默认 venue | ICLR/NeurIPS/ICML | **中文期刊/会议** |
| 论文结构 | 西方学术风格 | **中文期刊规范** |
| Figure 描述 | 英文 | 中文 |

## 关键规则

- **不要生成作者信息** — 作者信息留空或用占位符
- **对证据缺口诚实** — 将主张标记为"需实验验证"而非过度声明
- **页数预算是硬限制** — 如果内容超过限制，建议移至附录
- **主张-证据矩阵是骨干** — 每个主张必须映射到证据
- **Figure 需要详细描述** — 特别是主图，必须清楚说明展示内容
- **章节数是弹性的** — 根据论文类型可以是 5-7 节

## 调用示例

```

/paper-plan-zh "研究主题：遥感图像融合，已有实验结果在 results/"
```

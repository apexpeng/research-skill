# Research 2: 论文审查增强版

## 定位

聚焦于**论文审查环节**的增强，借鉴 Elicit/Deep Research 的文献调研能力和 Claude Scholar 的论证框架，对现有 `research` skill 的审查阶段进行深度升级。

> **注意**：不追求全流程自动化，专注"审"这一个环节做到极致。

## 与 v1 (research) 的区别

| 维度 | v1 | v2 |
|------|----|----|
| 审查标准 | 四维（证据链、逻辑、审稿人风险、结构）| 六维（新增：创新性、研究空白）|
| 证据验证 | 基础对照 | 深度溯源 |
| 文献关联 | 手动引用 | 自动推荐相关工作 |
| 假设验证 | 无 | 证据-主张对应检查 |
| 审查轮次 | 4轮 | 6轮（增强对抗性）|
| 跨模型审查 | 无 | 多模型独立评审 |

## 六维审查标准

### 1. 证据链完整性（30%）

与 v1 一致，检查每条主张是否有对应证据。

### 2. 逻辑严密性（20%）

与 v1 一致，检查推论链条。

### 3. 审稿人风险（15%）

与 v1 一致，检查过度声明、方法学漏洞。

### 4. 结构协调性（10%）

与 v1 一致，检查章节衔接。

### 5. 创新性评估（新增，15%）

- [ ] 贡献点是否明确
- [ ] 与现有工作的差异化是否清晰
- [ ] 是否避免了"首次"、"最优"等过度声明
- [ ] 创新点是否有具体支撑

### 6. 研究空白识别（新增，10%）

- [ ] 是否识别了领域内的研究空白
- [ ] 空白与贡献点的关联是否合理
- [ ] 相关工作覆盖是否全面（不仅限引用，还需讨论）

## 证据深度验证

v2 增强的证据检查：

```
主张 → 证据溯源 → 证据质量评估 → 证据与主张的关联度
```

### 证据质量分级

| 级别 | 来源 | 可信度 |
|------|------|--------|
| A | 同行评审论文、权威数据库 | 高 |
| B | 预印本、技术报告 | 中 |
| C | 个人博客、非正式发布 | 低（需说明）|

### 证据-主张对应检查

对每条核心主张，验证：
1. 是否有直接证据支持（非间接）
2. 证据来源是否可靠
3. 证据是否在正确位置被引用

## 跨模型对抗性评审（可选）

当 `ARIS_ADVERSARIAL_REVIEW=true` 时：

1. 使用第二个模型（不同于 Reviewer）进行独立评审
2. 两位评审者的分歧点需要 Executor 重点处理
3. 这种"对抗"可以避免单一模型的盲点

配置：
```bash
export ARIS_ADVERSARIAL_REVIEW=true
export ARIS_ADVERSARY_MODEL="MiniMax-M2.7"  # 或其他可用模型
```

## 阶段判定

与 v1 一致，但审查阶段采用六维标准：

| 条件 | 阶段 |
|------|------|
| 中文草稿存在 | `paper-review-loop` (v2 增强) |
| 评分 ≥ 6/10 且创新性≥B | 通过 |
| 第 6 轮仍不通过 | 需人工决策 |

## 输出文件

| 文件 | 说明 |
|------|------|
| `review_round_0X.md` | 六维审查记录（增强版）|
| `evidence_validation.md` | 证据溯源报告（新增）|
| `innovation_assessment.md` | 创新性评估报告（新增）|

## 常量

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `MAX_REVIEW_ROUNDS` | `6` | 最大审查轮次 |
| `POSITIVE_THRESHOLD` | `6/10` | 通过阈值 |
| `INNOVATION_THRESHOLD` | `B` | 创新性最低级别 |
| `ADVERSARIAL_REVIEW` | `false` | 是否启用对抗性评审 |
| `EVIDENCE_DEPTH_CHECK` | `true` | 是否启用证据深度验证 |

## 子 Skills 调用

与 v1 通用，审查阶段自动使用 v2 标准：

| Skill | 用途 |
|-------|------|
| `research-intake` | 立项阶段 |
| `research-draft` | 起草阶段 |
| `paper-figure` | 图表生成 |
| `paper-compile` | 编译 |

## 快速开始

```bash
# 使用 v2 审查标准
/research "主题"  # 自动使用 v2 审查

# 强制使用 v1 标准
/research "主题" --review-mode v1

# 启用对抗性审查
/research "主题" --adversarial
```

## 边界

- 本 skill 专注于审查增强，不改变其他阶段的基本流程
- 不追求全流程自动化，审稿人判断仍由人类最终负责
- 跨模型审查需要额外配置 API

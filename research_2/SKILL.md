# Research 2: 论文审查增强版

## 定位

`research_2` 是一个**独立入口**，专门用于强化论文审查环节。

它借鉴 Elicit / Deep Research 的文献对照能力和 Claude Scholar 风格的论证检查框架，但不追求“全流程自动科研”。它的职责很明确：**在已有主题、已有大纲或已有草稿的基础上，把“审”这一步做到更严格。**

适用输入包括：

- 已成型的 `draft_zh.md`
- 分章节稿件
- 摘要 + 结果 + 图表说明
- 接近投稿版本的完整稿件

## 与 v1 (`research`) 的关系

| 项目 | `research` | `research_2` |
|------|------------|--------------|
| 角色 | 四角色主流程 | 审查增强入口 |
| 主任务 | 写作编排、阶段推进 | 深度审查、问题暴露 |
| 审查轮次 | 最多 4 轮 | 最多 6 轮 |
| 适用时机 | 立项到成稿 | 投稿前 / 返修前 / 严格复核 |
| 调用方式 | `/research "主题"` | `/research_2 "草稿或主题"` |

**重要约定：**

- `research_2` 不是 `/research` 的隐式模式。
- 当前仓库中，如需启用 v2 审查，应**显式调用** `/research_2`。
- v2 不改写前面各阶段的基本流程，只增强审查标准与输出。

## 六维审查标准

### 1. 证据链完整性（30%）

检查每条核心主张是否有对应证据，是否存在悬空结论、证据错配或以讨论替代证据的问题。

### 2. 逻辑严密性（20%）

检查推论链条是否闭合，是否存在因果跳跃、概念偷换、结果外推过度等问题。

### 3. 审稿人风险（15%）

检查可能触发审稿人质疑的高风险点，例如：

- 过度声明
- 方法学漏洞
- 对照不足
- 统计支撑不足
- 结论超出数据边界

### 4. 结构协调性（10%）

检查摘要、引言、结果、讨论、方法之间是否协调，章节之间是否存在信息重复、断裂或叙事失衡。

### 5. 创新性评估（15%）

重点检查：

- 贡献点是否明确
- 与现有工作的差异化是否清晰
- 是否避免“首次”“最优”等不必要的绝对化表述
- 创新点是否有具体支撑，而不仅是口号式总结

### 6. 研究空白识别（10%）

重点检查：

- 是否识别了真实而非虚构的研究空白
- 空白与贡献点的对应是否合理
- 相关工作覆盖是否充分
- 是否只是“引用了文献”，而没有真正讨论竞争解释与已有方案

## 证据深度验证

v2 强化以下验证链条：

```text
主张 → 证据溯源 → 证据质量评估 → 证据与主张关联度 → 审稿风险提示
```

### 证据质量分级

| 级别 | 来源 | 可信度 |
|------|------|--------|
| A | 同行评审论文、权威数据库 | 高 |
| B | 预印本、技术报告 | 中 |
| C | 博客、非正式发布 | 低（需说明） |

### 对每条核心主张至少检查三件事

1. 是否有直接证据支持，而非只有间接暗示  
2. 证据来源是否可靠，是否需要降级表述  
3. 引用位置与结论位置是否匹配

## 对抗性评审（可选）

当 `ARIS_ADVERSARIAL_REVIEW=true` 时，可使用第二模型进行独立评审：

1. Reviewer A 给出第一轮六维审查
2. Reviewer B 做独立复核
3. Executor 优先处理两位评审分歧最大的部分
4. Supervisor 检查是否真正处理了冲突点

配置示例：

```bash
export ARIS_ADVERSARIAL_REVIEW=true
export ARIS_ADVERSARY_MODEL="MiniMax-M2.7"
```

## 阶段与通过条件

| 条件 | 结果 |
|------|------|
| 已有中文草稿 | 进入 v2 review loop |
| 总评分 ≥ 6/10 且创新性不低于 `B` | 通过 |
| 第 6 轮仍不通过 | 输出 `需人工决策` |

## 输出文件

| 文件 | 说明 |
|------|------|
| `review_round_0X.md` | 六维审查记录 |
| `evidence_validation.md` | 证据溯源报告 |
| `innovation_assessment.md` | 创新性评估报告 |
| `review_risk_register.md` | 高风险问题清单（建议新增） |

## 运行时常量

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `MAX_REVIEW_ROUNDS` | `6` | 最大审查轮次 |
| `POSITIVE_THRESHOLD` | `6/10` | 通过阈值 |
| `INNOVATION_THRESHOLD` | `B` | 创新性最低级别 |
| `ADVERSARIAL_REVIEW` | `false` | 是否启用对抗性评审 |
| `EVIDENCE_DEPTH_CHECK` | `true` | 是否启用证据深度验证 |

## 推荐使用方式

```bash
# 对已有草稿做严格审查
/research_2 "深度审查草稿"

# 对接近投稿版本的稿件做六维审查
/research_2 "投稿前终稿审查"

# 启用对抗性评审（先配置环境变量）
/research_2 "对抗性审查：草稿"
```

## 边界

- 本 skill 专注审查增强，不负责替代完整写作主流程
- 它不会自动接管 `/research` 的审查阶段
- 最终投稿判断仍应由人类作者负责
- 跨模型评审需要额外 API 配置
